Found four concrete mismatches or enforcement gaps:

1. **“Already resolved” is not strictly enforced.** The README limits final drafting to resolved determinations ([README:103](./README.md#L103), [README:172](./README.md#L172)). But `parseRespondeoStatus` treats everything except a first-nonempty-line `STATUS: NEEDS_INPUT` as `RESOLVED`—including empty text, malformed statuses, and saved judge-failure messages ([debate.ts:124](./src/debate.ts#L124)). `--finalize` uses that permissive check ([index.ts:234](./src/index.ts#L234)). A fake-CLI test confirmed that a saved `Respondeo turn failed: …` produces a final report successfully.

2. **Continuation does not require a prior `NEEDS_INPUT` determination.** The documented workflow answers an unresolved judge’s questions ([README:95](./README.md#L95), [README:177](./README.md#L177)). Implementation loads the latest determination and re-judges without checking its status ([index.ts:209](./src/index.ts#L209), [index.ts:255](./src/index.ts#L255)). Its prompt nevertheless states that the prior determination “ended in NEEDS_INPUT” ([debate.ts:170](./src/debate.ts#L170)). A fake-CLI test confirmed that an already-resolved determination is accepted.

3. **The configured-judge requirement has an undocumented exception.** The README says everything from respondeo onward runs “only when the config defines a `judge`” ([README:158](./README.md#L158)). This holds for fresh debates, but both saved-debate commands use the **current configuration’s judge**, falling back to Claude Opus, high effort, with a $5 budget ([index.ts:103](./src/index.ts#L103), [index.ts:214](./src/index.ts#L214)). They do not restore the original debate’s judge. Both still require an existing saved determination.

4. **The stdout fallback differs for continuations.** The README promises `final-report.md` when produced, otherwise `debate.md` ([README:107](./README.md#L107)). An unresolved continuation instead prints `respondeo-N.md` and exits **0** ([index.ts:270](./src/index.ts#L270)). The same happens when re-judging resolves but final drafting fails ([index.ts:285](./src/index.ts#L285)). Both behaviors were reproduced with fake CLIs.

The important workflow claims do hold, subject to the status-parsing gap:

- **Phase ordering:** fresh debates run proposals, reactions, then the configured judge; fewer than two successful proposals abort before judging. A determination classified as resolved triggers synthesis. `--continue` re-judges without debaters; `--finalize` only synthesizes ([README:162](./README.md#L162), [README:202](./README.md#L202); [debate.ts:221](./src/debate.ts#L221), [debate.ts:253](./src/debate.ts#L253); [index.ts:234](./src/index.ts#L234)).
- **Saved-state selection:** `--debate` wins; otherwise both commands select the lexicographically latest `.debate/debate-*` directory under the current working directory. Within it, they select the highest **numeric** respondeo version, with unnumbered `respondeo.md` treated as version 1 ([README:95](./README.md#L95), [README:188](./README.md#L188); [index.ts:124](./src/index.ts#L124)). Continuation leaves `debate.md` unchanged; the latest ruling is supplied separately.
- **Repository evidence:** initial judging and re-judging receive transcript context, with no repository worktree supplied. Final drafting receives `--repo` or the current config’s repository and runs in a disposable worktree of **HEAD**, consistent with the documented deliverable grounding ([README:99](./README.md#L99), [README:175](./README.md#L175); [index.ts:217](./src/index.ts#L217), [debate.ts:188](./src/debate.ts#L188), [debate.ts:261](./src/debate.ts#L261)).
- **Successful drafting prints `final-report.md`.** Fresh debates without a deliverable print `debate.md` ([index.ts:249](./src/index.ts#L249), [index.ts:281](./src/index.ts#L281), [index.ts:403](./src/index.ts#L403)).
