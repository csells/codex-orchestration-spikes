Found two documentation mismatches and two status-enforcement gaps.

1. **“Only when resolved” is not reliably enforced.** README says final-report drafting runs only after resolution and describes `--finalize` as operating on an already-resolved debate ([README.md:103](README.md#L103), [README.md:172](README.md#L172)). But `parseRespondeoStatus` treats anything except a first nonempty line matching `STATUS: NEEDS_INPUT` as `RESOLVED`, including missing/malformed status text ([src/debate.ts:120](src/debate.ts#L120)). More seriously, an initial judge failure produces saved text such as `Respondeo turn failed: budget`; `--finalize` accepts that because it rejects only `NEEDS_INPUT` ([src/debate.ts:263](src/debate.ts#L263), [src/index.ts:235](src/index.ts#L235)). Fake-CLI checks confirmed successful finalization from both failure text and a statusless determination.

2. **`--continue` does not require a prior `NEEDS_INPUT`.** README presents continuation as answering an unresolved judge’s questions ([README.md:95](README.md#L95), [README.md:177](README.md#L177)). The CLI loads the latest determination and re-judges without checking its status ([src/index.ts:209](src/index.ts#L209), [src/index.ts:255](src/index.ts#L255)). The prompt even asserts that the prior determination “ended in NEEDS_INPUT” regardless of its contents ([src/debate.ts:170](src/debate.ts#L170)). A fake-CLI check confirmed continuation accepts `RESOLVED`. This is an unenforced workflow precondition, rather than an explicitly documented rejection guarantee.

3. **The config-only judge claim needs an exception.** README says everything from respondeo onward runs “only when the config defines a `judge`” ([README.md:158](README.md#L158)). That holds for new debates, but both saved-debate commands use the **current config’s judge**, falling back to Claude Opus with high effort and a $5 budget—not a judge recovered from the saved debate ([src/index.ts:103](src/index.ts#L103), [src/index.ts:214](src/index.ts#L214)). Fake-CLI checks confirmed both fallback and configured-model selection.

4. **The stdout contract omits continuation’s determination path.** README promises `final-report.md` when produced, otherwise `debate.md` ([README.md:107](README.md#L107)). An unresolved continuation instead prints `respondeo-N.md` and exits **0**. It also prints that determination path if subsequent final-report drafting fails ([src/index.ts:265](src/index.ts#L265), [src/index.ts:278](src/index.ts#L278)). The unresolved case was reproduced with a fake CLI.

The important claims that hold:

- **Phase order:** a new debate runs proposals, reactions, then the configured judge. Fewer than two successful proposals abort before judging. A recognized `NEEDS_INPUT` or failed judge suppresses automatic final-report drafting ([README.md:162](README.md#L162), [src/debate.ts:221](src/debate.ts#L221), [src/debate.ts:253](src/debate.ts#L253)).
- **Saved-state selection:** explicit `--debate` wins; otherwise the CLI selects the lexically latest timestamp-named directory under the current working directory’s `.debate`.
