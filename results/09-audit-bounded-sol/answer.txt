The phase order mostly matches the README, but there are two documentation mismatches and two status-enforcement gaps.

1. **“Resolved-only” drafting is not enforced.** The README describes `--finalize` as drafting from an already-resolved debate and says reports run only when the determination resolves ([README.md:103](<WORKSPACE>/README.md:103), [README.md:172](<WORKSPACE>/README.md:172)). However, the parser treats anything except an explicit first-line `STATUS: NEEDS_INPUT` as `RESOLVED`, including empty or malformed text ([debate.ts:120](<WORKSPACE>/src/debate.ts:120)). Consequently, `--finalize` also accepts a saved `Respondeo turn failed: ...` artifact: it rejects only `NEEDS_INPUT` ([index.ts:234](<WORKSPACE>/src/index.ts:234)). A fake-CLI check reproduced successful report generation from such a saved failure.

2. **Continuation does not require `NEEDS_INPUT`.** The documented workflow presents continuation as answering the judge’s open questions ([README.md:177](<WORKSPACE>/README.md:177)). The implementation loads the saved determination and re-judges without checking its prior status ([index.ts:209](<WORKSPACE>/src/index.ts:209), [index.ts:255](<WORKSPACE>/src/index.ts:255)). This is an unenforced workflow precondition, rather than a contradiction of an explicit rejection promise. A fake-CLI check confirmed continuation from `RESOLVED`.

3. **The configured-judge requirement has an undocumented exception.** The README says the judge and subsequent phases run “only when the config defines a `judge`” ([README.md:158](<WORKSPACE>/README.md:158)). That holds for new debates. Both resumed commands instead use the **current configuration’s judge**, falling back to built-in Claude Opus when absent; they do not restore the original judge ([index.ts:214](<WORKSPACE>/src/index.ts:214)). Thus resumption can change judges and needs no configured judge.

4. **Unresolved continuation contradicts the stdout contract.** The README promises `final-report.md` when produced, otherwise `debate.md` ([README.md:107](<WORKSPACE>/README.md:107)). An unresolved continuation instead prints the new `respondeo-N.md` and exits zero. The same fallback occurs when continuation resolves but report drafting fails ([index.ts:270](<WORKSPACE>/src/index.ts:270), [index.ts:285](<WORKSPACE>/src/index.ts:285)).

Important claims that hold:

- A new debate requires at least two successful proposals, completes its reaction rounds, then runs a configured judge. A successful determination parsed as `RESOLVED` triggers drafting; explicit `NEEDS_INPUT` or a failed judge does not ([debate.ts:228](<WORKSPACE>/src/debate.ts:228)).
- Both resumed commands select explicit `--debate`, otherwise the lexicographically latest `.debate/debate-*` directory, then the highest-numbered saved determination—not the latest *resolved* determination ([index.ts:134](<WORKSPACE>/src/index.ts:134)). `--finalize` skips re-judging and rejects explicit `NEEDS_INPUT`.
- Judging and re-judging receive transcript evidence, not repository access. `--repo` supplies repository access to final-report drafting, matching the README’s deliverable-grounding claim ([README.md:99](<WORKSPACE>/README.md:99), [debate.ts:188](<WORKSPACE>/src/debate.ts:188)).
- Successful drafting prints `final-report.md`; a new debate without a report prints `debate.md`.
